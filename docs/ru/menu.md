# Меню в терминале

Команда `linager` без аргументов открывает интерактивное меню: логотип, состояние и пронумерованные действия. Подкоманды (`linager update`, `linager backup` и остальные) работают как раньше; в скриптах, по cron и в конвейере (когда нет терминала) `linager` по-прежнему печатает справку.

```bash
sudo linager            # меню
sudo linager --lang en  # меню на английском (по умолчанию язык берётся из LANG)
```

Без `sudo` меню тоже откроется, но конфигурация, база и ключи закрыты для обычного пользователя: часть строк будет помечена «нужен root», а пункты, которым нужны права, запустятся через `sudo` (рядом с ними написано `sudo`).

## Как определяется режим

Меню смотрит на диск, а не на сервер:

| Что найдено | Что показано |
|---|---|
| `/etc/linager/server.yaml` или `linager-server.service` | меню сервера |
| `/var/lib/linager-agent/state.json` или `linager-agent.service` | меню агента |
| оба | экран выбора: две карточки с состоянием, клавиши `1` и `2` |
| ничего | предложение установить сервер или агент |

Состояние обновляется каждые 5 секунд. Если что-то не читается (например, лежит база), строка так и скажет, а меню останется доступным. Установка или удаление из самого меню сразу меняют экран.

## Меню сервера

Состояние: служба и время работы, PostgreSQL, порт приложения, порт клиентов, число клиентов и ожидающих подтверждения, последний бэкап, ограничение доступа, версия (и доступное обновление, оно проверяется раз в 30 минут).

| Пункт | Что делает |
|---|---|
| 1 | `linager update` |
| 2 | `linager backup` |
| 3 | список архивов (до 9), подтверждение, `linager restore <архив> --yes` |
| 4 | пароль администратора: `server create-admin`, если пользователей ещё нет, иначе `server reset-password` |
| 5 | подтверждение, `linager access reset` |
| 6 | отпечаток сервера, порт клиентов и готовая команда для клиента |
| 7 | подтверждение, `systemctl restart linager-server` |
| 8 | `journalctl -u linager-server -f`; выход из логов: `Ctrl+C` |
| 0 | назад (если на хосте два режима) или выход |

## Меню агента

Состояние: служба, адрес сервера (или «не подключён»), включённые модули, версия.

| Пункт | Что делает |
|---|---|
| 1 | спрашивает адрес и отпечаток, `linager agent enroll`; если агент уже подключён, сначала подтверждение |
| 2 | `linager agent update` |
| 3 | подтверждение, `systemctl restart linager-agent` |
| 4 | `journalctl -u linager-agent -f` |
| 5 | выбор «ключи оставить» или «вместе с ключами» (`--purge`), `linager agent uninstall` |

## Как это устроено

- Пункты запускают те же подкоманды, что и в терминале: меню на время приостанавливается, вывод остаётся на экране до нажатия Enter.
- Опасные действия (восстановление, сброс ограничения доступа, перезапуск службы) требуют подтверждения; `Enter` подтверждением не считается, нужна `y`.
- Действия сервера из меню (обновление, бэкап, восстановление, перезапуск, создание администратора) пишутся в журнал аудита с пометкой «CLI» и признаком `via: menu`. Сброс ограничения доступа и сброс пароля пишут запись сами.
- Пароль для пунктов 4 передаётся через временный файл с правами 600, он удаляется сразу после команды.

## Сброс пароля администратора

Новая команда, которой меню пользуется в пункте 4. Её можно вызвать и отдельно:

```bash
echo 'новый пароль' | sudo linager server reset-password --login admin --password-file -
```

Команда меняет пароль, снимает блокировку входа и завершает все сессии пользователя. Двухфакторная защита не отключается.
