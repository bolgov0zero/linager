# Приложение Linager

Приложение для рабочего стола (macOS, Windows, Linux) показывает интерфейс сервера в нативных окнах. Оно заменило веб-панель (удалена в 0.10.0-beta.17): это единственный интерфейс сервера. Сервер ставится установщиком в терминале (`linager install server`), приложение подключается к уже готовому серверу.

**Состояние (этап 2).** Есть страница сервера: Обзор, Метрики, Терминал, Службы, Процессы, Логи, Обновления, Диск, Файлы (дерево и таблица), Сеть, Файрвол, Безопасность, Пользователи, Docker; опасные действия с подтверждением. Все вкладки редактируются: пользователи, сеансы SSH, fail2ban и ключи, сеть и файрвол (с откатом через 30 секунд), Docker (контейнеры, образы, правка контейнера). Отдельные окна: терминал (выбор пользователя, сниппеты, «Файлы», «Диспетчер»), заметка, файлы, диспетчер, редактор файла. Консоль: список серверов, вкладки сеансов, терминалы, Помощник, RDP и Ключи (кнопка с ключом в верхней панели, файл открывается и сохраняется через диалоги системы). Вкладки Windows (пользователи, Windows Update, программы, сетевые адаптеры). До этого было: подключение с проверкой сертификата, вход (логин, пароль, 2FA), дашборд в трёх видах (карточки, компактные карточки, строки), светлая и тёмная тема, русский и английский, терминал в отдельном окне. Самообновление по кнопке в «Настройки → Обновления». Трей: значок в области уведомлений (ниже). Пока нет: уведомления, подписанные и нотаризованные сборки, вход по passkey (удалён).

## Подключение

1. В «Настройки → Подключение» сервера включён **порт приложения** (его спрашивает установщик). Там же показан отпечаток сертификата.
2. В приложении введите `адрес:порт`. Приложение подключится и покажет отпечаток сертификата сервера.
3. Сверьте его с отпечатком в настройках сервера или в итогах установки и подтвердите. Приложение запомнит отпечаток и в дальнейшем примет только этот сертификат (как SSH запоминает ключ хоста). Если сертификат когда-нибудь изменится, приложение откажется подключаться и предупредит.
4. Войдите. Пароль можно сохранить в связке ключей системы (Keychain на macOS, Credential Manager на Windows, Secret Service на Linux); тогда вход идёт сам, код 2FA, если он включён, спрашивается всё равно.

Сессия живёт семь дней и продлевается при каждом обращении к серверу (даже обычная работа с дашбордом считается): пока приложением пользуются, входить заново не нужно, а после семи дней без активности снова спросят пароль и 2FA. Cookie сессии приложение хранит в связке ключей и забывает при выходе. Для браузерной панели сессия, как раньше, 12 часов. Нужен сервер 0.10.0-beta.4 или новее.

Список серверов и последний логин лежат в `<конфигурация пользователя>/Linager/profiles.json` (права 600, ничего секретного: отпечаток публичен). Рядом лежит `vault-last.json` помнит путь к выбранному файлу ключей (Ключи) семь дней, как сам вход; пароль к файлу не хранится. `prefs.json`: тема, язык, вид дашборда, сортировка строк и раздел верхней панели (Дашборд или Консоль), чтобы они сохранялись между запусками.

## Как устроено

Внутри приложения работает локальный сервер на `127.0.0.1`. Все пути на нём начинаются со случайного токена (его не знает ни другая программа, ни веб-страница), запросы с другим `Host` отклоняются (защита от DNS rebinding). Окна открывают его адрес.

- Интерфейс отдаётся из самого приложения.
- API сервера проксируется по TLS 1.3 с закреплением отпечатка. Проверка идёт при каждом соединении. Cookie сессии хранится в приложении, до страницы она не доходит. SSE (живые данные) и WebSocket (терминал) идут через тот же прокси.
- Собственные вызовы (`/app/...`): профили, связка ключей, открытие окон.

Интерфейс (`app/frontend`, Svelte) не зависит от Wails, поэтому его можно открыть и в приложении: `make -C app headless` печатает адрес.

## Где взять приложение

Готовые файлы лежат в [релизах](https://github.com/bolgov0zero/linager/releases) (с `0.10.0-beta.4`, пока это беты):

| Система | Файл | Что внутри |
|---|---|---|
| macOS (только Apple Silicon) | `linager-desktop_macos_arm64.zip` | `Linager.app` |
| Windows 10/11 x64 | `linager-desktop_windows_x64.msi` (установщик), `linager-desktop-autoupdate_windows_x64.zip` (архив для самообновления; годится и как переносная копия) | `linager-app.exe` (нужен WebView2, в Windows 11 он есть) |
| Linux x64 | `linager-desktop_linux_x64.tar.gz` | `linager-app` (нужны `libgtk-4` и `libwebkitgtk-6.0`) |

Распакуйте и запустите. Сборки не подписаны разработчиком и не нотаризованы: на macOS первый раз откройте приложение через контекстное меню (правый клик, «Открыть»); если macOS пишет, что файл повреждён (так бывает с zip, скачанным из сети), снимите карантин: `xattr -dr com.apple.quarantine Linager.app`. Windows покажет SmartScreen. Для Windows есть и установщик `linager-desktop_windows_x64.msi`: он ставит приложение только для текущего пользователя (права администратора не нужны) в `%LocalAppData%\Programs\Linager`, добавляет ярлык в меню «Пуск» и запись в «Приложения», самообновление оттуда работает. Для Linux в архиве лежат `linager.desktop` и `linager.png` для меню рабочего стола (команды в `README.txt` архива). Положите приложение туда, где у вас есть право записи (для macOS это `~/Applications` или `/Applications` под администратором): самообновление заменяет файлы на месте.

Контрольные суммы всех файлов лежат в `SHA256SUMS` и в подписанном `manifest.json` той же релизной подписью (minisign), что и у сервера и агента.

## Обновление приложения

**Компактные карточки.** Внизу карточки вместо адреса стоят значки с числами, когда есть на что посмотреть: упавшие службы (красный), нужна перезагрузка (янтарный), обновления системы и обновления образов Docker (синий, а при 10 и больше пакетах или 5 и больше образах янтарный). Значков не больше трёх, остальные свёрнуты в «+N» (подсказка перечисляет их). У сервера без связи стоит «нет связи» и известные обновления серым. Нет замечаний: виден адрес.

Шестерёнка в верхней панели открывает **Настройки** в отдельном окне. Разделы: «Приложение» (то, что описано ниже), «Профиль» (пароль, 2FA, коды восстановления), «Сниппеты», «Папки» (дерево папок серверов, см. ниже), «Теги» (справочник тегов: переименовать, выбрать цвет из 16, удалить, создать новый; у каждого видно, на скольких серверах он стоит и скольким пользователям по нему выдан доступ), «Пользователи» (роли, серверы, папки, теги и модули оператора) «Доступ к серверу» (белый или чёрный список адресов, которым можно подключаться к порту приложения, проверка адреса, журнал подключений приложения; он отдельный от доступа к админке, и пока не сохранён, порт следует ему; имена хостов (DDNS) разрешаются через DNS раз в минуту, как в приложении), «Подключение» (порты агентов и приложения) «Обновления» (сервера и агентов: проверка, обновление, кэш релизов, история) и «Журнал» (журнал аудита). Оператор и аудитор видят только «Приложение» и «Профиль». Все разделы настроек панели перенесены. **Добавить сервер** (кнопка на дашборде): подтверждения (агенты, которые просятся, и данные для ручного подключения), установка по ссылке и установка по SSH. Режим правки дашборда (кнопка «Редактировать»): порядок карточек (перетаскиванием или стрелками), папка сервера, убрать с дашборда (пять секунд на отмену; вернуть можно в «Добавить сервер → Подтверждения») и удалить сервер. Окно приложения не уменьшается меньше 1340 на 851. **Настройки → Приложение**: версия, канал (выбирается: «Бета» предлагает все выпуски, «Стабильный» только готовые; по умолчанию канал текущей версии), кнопки «Проверить» и «Обновить и перезапустить». Приложение проверяет релизы при запуске и раз в шесть часов (в настройках это можно выключить); на шестерёнке появляется точка, когда есть новая версия. **Ставится только по вашей кнопке.**

**Папки.** «Настройки → Папки» это дерево папок серверов, вложенность до 8 уровней (бывшие группы стали папками верхнего уровня). Сервер лежит ровно в одной папке, на любом уровне; серверы вне папок собраны в «Без папки». Строки перетаскиваются: линия между строк меняет порядок, перетаскивание на папку кладёт внутрь (закрытая папка раскрывается через долю секунды, у края окна список прокручивается, Esc отменяет жест); так же переносятся серверы. Есть меню «⋯» и правый щелчок (новая подпапка, переименовать, «Переместить в», удалить), двойной щелчок и F2 переименовывают, Del удаляет, Alt+↑/↓ меняет порядок. Название уникально внутри родителя; папку нельзя положить в себя или в свою подпапку. **Доступ, выданный папке, действует на все её серверы и вложенные папки, в том числе будущие**, поэтому перенос и удаление, которые меняют, кто что видит, показывают, кто теряет и кто получает какие серверы, и просят подтверждения (в журнале аудита `group.move`, `group.delete`, `group.assign` с числом затронутых пользователей). При удалении подпапки папки встают на её место, серверы поднимаются на уровень выше, а доступ, выданный именно этой папкой, пропадает. Создание, переименование и перенос можно отменить кнопкой внизу. Фильтр по папке на дашборде включает всё её поддерево, в Консоли дерево папок стоит в боковом списке.

**Лимит GitHub.** Проверка читает список выпусков из API GitHub, а он разрешает адресу 60 запросов в час (неизменившийся список отвечает «не изменился» и ничего не стоит). Если несколько компьютеров делят один адрес и лимит исчерпан, приложение говорит, когда можно спросить снова. Необязательный **токен GitHub** («Настройки → Приложение → Обновления»; достаточно fine-grained токена для публичных репозиториев без разрешений) переносит запросы на лимит токена, 5000 в час; он хранится в связке ключей системы и уходит только с запросом списка.

Что происходит по кнопке: приложение читает список релизов с GitHub, берёт самый новый с файлом для вашей системы, проверяет подпись `manifest.json` и версию в нём, скачивает файл и сверяет размер и sha256 с подписанным манифестом, распаковывает рядом с собой и подменяет себя (на macOS целиком подменяется `Linager.app`, при сбое старая копия возвращается; на Windows старый файл переименовывается в `.old` и удаляется при следующем запуске), затем запускает новую версию и закрывается. Неподписанный или не совпавший с манифестом файл не ставится никогда. Сборка из рабочей копии (`make run`, версия `dev`) и запуск без окна (`-headless`) не обновляются.

Первую бету с приложением (`0.10.0-beta.4`) поставьте руками, дальше обновления приходят через приложение. Если нужен свой сборочный экземпляр, соберите из исходников (нужны Go, Node.js и Xcode Command Line Tools для macOS):

```bash
make -C app bundle   # app/bin/Linager.app
make -C app zip      # app/bin/linager-desktop_macos_arm64.zip (или x86_64 на Intel), чтобы передать на другой Mac
```

## Трей

Приложение живёт в области уведомлений (строка меню macOS, трей Windows и Linux). Значок: логотип без фона; на macOS его красит система, на Windows и Linux он тёмный или белый по теме панели. Закрытие окна **прячет** приложение в трей, а не завершает его; значок Dock остаётся. Выйти можно пунктом «Закрыть» меню значка или клавишами Cmd+Q. Щелчок по значку любой кнопкой мыши открывает его меню (пункт «Открыть» возвращает окно). Второй запуск не открывает вторую копию, а показывает окно первой.

Меню значка: «Открыть» (первый пункт), строка состояния («В сети 12 из 15, внимание: 2, ждут: 1»: пороги те же, что на дашборде; «ждут» это агенты, которые просят подтверждения), выбранные вами подключения и «Закрыть» (последний пункт). Когда есть серверы с проблемой или ждущие агенты, на macOS рядом со значком стоит число, а на Windows и Linux на значке красная точка.

**Меню удалённого экрана** (Ассистент и RDP). «Отображение»: режимы картинки (по размеру окна, растянуть, 100% с прокруткой мышью у краёв окна: у края картинка плавно едет в эту сторону), «Окно по размеру картинки» (окно Ассистента подгоняется под размер экрана компьютера в пределах рабочей области) и полный экран последним; действующий режим подсвечен. «Ещё»: диспетчер задач, клавиша Windows, блокировка, «Выполнить», переключение окон (сочетания показаны справа), буфер обмена, мониторы, информация, качество и «Отключиться». «Сеанс»: номер, пользователь (без домена), адрес клиента RDP и вид сеанса бейджем.

**Подключения в трее.** На странице сервера рядом с кнопкой «Заметка» есть кнопка с шестерёнкой: настройки сервера. В них два блока. «Теги»: метки сервера, хранятся на сервере Linager в общем справочнике (до 20 тегов по 32 символа на сервер, до 200 разных; менять может администратор; действие пишется в журнал аудита как `server.tags` с числом пользователей, у которых из-за этого изменился доступ). Новое имя создаёт тег в справочнике; при вводе открывается свой список существующих тегов в их цветах (фильтр по набранному, стрелки выбирают, Enter добавляет, Esc закрывает; новое имя предлагается последней строкой «Создать тег»). **Теги на дашборде:** на больших и компактных карточках слева от кнопок, в строках отдельной колонкой «Теги». Тег показан первой буквой на цвете тега; при наведении выезжает полное имя поверх соседей (раскладка не двигается). Что не помещается (3 на большой карточке, 2 на компактной, 5 в строке), сворачивается в «+N»; при наведении на него видны имена. Названия, цвета и удаление тегов: «Настройки → Теги». Тегом можно выдать доступ пользователю (роли и доступ: [security.md](security.md)). «В трее»: подключения терминал, RDP и Помощник (сколько угодно, только те, что есть у этого сервера). Выбранное появляется в меню значка: значок подключения и имя сервера; щелчок открывает окно с этим подключением. Список хранится в `tray.json` рядом с профилями, отдельно для каждого сервера Linager.

**Запуск при входе.** «Настройки → Приложение → Запускать при входе в систему»: приложение стартует при входе в систему с окном, спрятанным в трее (macOS: агент запуска в `~/Library/LaunchAgents`, Windows: ключ реестра `Run` пользователя, Linux: файл автозапуска в `~/.config/autostart`). После самообновления новая версия ждёт, пока старая завершится, и только потом стартует.

На Linux трею нужен рабочий стол со значками StatusNotifier (KDE, GNOME с расширением AppIndicator). Без него закрытое окно значком не вернуть: запустите приложение из меню ещё раз, и покажется окно уже работающей копии.

## Сборка и запуск

```bash
make -C app test       # тесты интерфейса и Go-пакетов
make -C app run        # окно приложения
make -C app headless   # только интерфейс на локальном адресе, без окна
```

Нужны Go и Node.js. macOS: Xcode Command Line Tools. Windows: сборка без CGO, на машине должен быть WebView2 (в Windows 11 есть). Linux: `libgtk-4-dev` и `libwebkitgtk-6.0-dev`. Сборка проверяется в CI на всех трёх системах (`.github/workflows/app.yml`).

## Ограничения этапа 1

- **Passkey** удалены (0.10.0-beta.17): приложение не могло ими пользоваться, адрес окна (`127.0.0.1`) не совпадает с адресом сервера. Вход по логину, паролю и 2FA.
- **Linux:** нужен WebKitGTK 6.0 (Debian 13, Ubuntu 24.04 и новее). На Debian 12 и Ubuntu 22.04 не проверялось.
- **Подпись:** приложение не подписано и не нотаризовано (macOS попросит открыть его через контекстное меню, Windows покажет SmartScreen).
