# Агент для Windows

Агент работает на Windows 10 / 11 и Windows Server 2016 и новее (x64) и подключается к серверу Linager так же, как Linux-агент. **Сервер остаётся на Linux.** В Windows-агенте только модули, которые прямо ложатся на Windows.

## Что работает

| Вкладка | Что делает в Windows |
|---|---|
| Метрики | процессор, память, подкачка, диски (каждый том с файловой системой), сетевые адаптеры и скорость, время работы, процессы, «нужна перезагрузка» (Windows Update). Средней нагрузки (load average) в Windows нет: показывается 0. |
| Терминал | PowerShell (cmd.exe, если его нет) в псевдоконсоли (ConPTY, Windows 10 1809 / Server 2019 и новее). Оболочка работает от имени **SYSTEM**, с полным доступом агента, как root-оболочка в Linux. Всё пишется в журнал аудита. |
| RDP | экран компьютера в браузере (RDP через агента), см. «RDP» ниже. |
| Помощник | экран консоли или чужого сеанса RDP без нового сеанса, см. «Помощник и «Управление»» ниже. |
| Службы | список из диспетчера служб (SCM): запуск, остановка, перезапуск, тип запуска (включить = автоматически, отключить = отключена). Подтверждение требуют сам агент, удалённый рабочий стол, WinRM, sshd, службы RPC, DHCP, DNS и файрвола. Автоматическая служба, которая остановилась с ошибкой, считается сбойной. |
| Процессы | список с процессором, памятью, пользователем и командной строкой; «завершить» (в Windows один способ завершить процесс, поэтому «завершить» и «убить» делают одно и то же). Системные процессы (csrss, lsass, services, wininit, winlogon, smss, System) отклоняются. |
| Журналы | журналы событий Windows в реальном времени: по умолчанию System и Application; в поле «служба» можно указать классический журнал (`Security`, `Setup`), журнал событий приложений (`Microsoft-Windows-TaskScheduler/Operational`) или имя источника (например `Service Control Manager`). «Ядро» показывает источники ядра. Приоритет переводится в уровень (ошибка, предупреждение, информация). |
| Файлы | файловый менеджер. Верх дерева это список дисков, пути выглядят как `/C:/Users/x`. Владелец и группа не показываются, права из панели менять нельзя (в Windows ACL). Корни дисков, `C:\Windows`, `C:\Program Files`, `C:\ProgramData`, `C:\Users` нельзя переименовать, удалить или заменить. |
| Перезагрузка | `shutdown /r`, с подтверждением. |

В Windows недоступно (вкладки скрыты): файрвол, безопасность (fail2ban, ключи), Docker. Пользователи, обновления и сеть имеют свой вид для Windows, см. ниже.

## Установка

Скачайте `linager-agent_windows_amd64.msi` из релиза (сверьте с `SHA256SUMS`) и установите из командной строки с правами администратора:

```powershell
msiexec /i linager-agent_windows_amd64.msi /qn SERVER=panel.example.com:9443
```

`SERVER` это порт агентов сервера (`хост:порт`). `FINGERPRINT=SHA256:...` необязателен: с ним агент доверяет только сертификату с этим отпечатком; без него привязку защищает проверочный код (см. ниже). Пакет ставит `C:\Program Files\Linager\linager.exe`, регистрирует службу **Linager Agent** (`LinagerAgent`, автозапуск, работает от SYSTEM, после сбоя запускается снова) и запускает её.

### Установка по ссылке (одна команда)
Самый простой способ: в панели откройте «Добавить сервер», вкладка «Установка по ссылке», создайте ссылку и переключите команду на **Windows**. На новом компьютере откройте PowerShell **от имени администратора** и вставьте команду. Она проверяет сертификат вашего сервера по отпечатку (он есть в самой команде), скачивает установщик с сервера, сверяет его с подписанным релизом, передаёт службе одноразовый код ссылки через файл, который могут читать только SYSTEM и администраторы (`C:\ProgramData\Linager\agent\join.token`), устанавливает и запускает службу. Компьютер появляется во вкладке «Подтверждения» и подтверждается одним нажатием: ключ копировать и файлы открывать не нужно. Скрипт можно прочитать заранее по адресу `https://<сервер>/v1/join/<ссылка>/windows`.

### Установка из локального файла
Скачайте `linager-agent_windows_amd64.msi` и `SHA256SUMS` из релиза (или возьмите файл с сервера: `https://<сервер>/v1/join/<ссылка>/msi`), сверьте контрольную сумму (`Get-FileHash -Algorithm SHA256 .\linager-agent_windows_amd64.msi`), скопируйте MSI на компьютер и в PowerShell от администратора выполните:

```powershell
msiexec /i C:\путь\linager-agent_windows_amd64.msi /qn SERVER=хост:порт FINGERPRINT=SHA256:...
```

Адрес это порт агентов сервера, отпечаток показан в панели (он есть и в команде установки по ссылке). Затем подтвердите компьютер во вкладке «Подтверждения» ключом из `C:\ProgramData\Linager\agent\enroll.txt`. Чтобы подтверждение было одним нажатием и без ключа, создайте в панели ссылку и до установки запишите её код в защищённый файл:

```powershell
New-Item -ItemType Directory -Force C:\ProgramData\Linager\agent | Out-Null
icacls C:\ProgramData\Linager /inheritance:r /grant:r '*S-1-5-18:(OI)(CI)F' '*S-1-5-32-544:(OI)(CI)F'
Set-Content C:\ProgramData\Linager\agent\join.token 'lk_...' -NoNewline -Encoding ASCII
```

### Привязка
1. В панели откройте «Добавить сервер», вкладка «Подтверждения»: узел появится там через несколько секунд после запуска службы.
2. На Windows-машине прочитайте ключ и проверочный код (доступно только администраторам):

   ```powershell
   Get-Content C:\ProgramData\Linager\agent\enroll.txt
   ```

3. Введите ключ («Ключ подтверждения») и **убедитесь, что проверочный код совпадает**: он связывает ключ с сертификатом, который увидел агент, и защищает привязку от посредника, когда отпечаток не задан. Подтвердите.

То же из консоли: `& "C:\Program Files\Linager\linager.exe" agent enroll --server panel.example.com:9443`. Служба замечает новую привязку в течение 10 секунд.

## Пользователи, обновления и сеть
Эти вкладки работают и в Windows, со своим видом (без оболочек и sudo): **Пользователи** (локальные учётные записи и группы), **Обновления** (Windows Update), **Программы** (установленные программы) и **Сеть** (адаптеры).

- **Пользователи.** Список локальных учётных записей: имя, полное имя, включена ли, последний вход, группы. Добавить пользователя (пароль обязателен: Windows не пускает по сети без пароля), задать пароль, включить или отключить, изменить группы (например «Администраторы» или «Пользователи удалённого рабочего стола»), удалить. Сеансы, которые сейчас открыты (консоль и удалённые рабочие столы), с кнопкой «Завершить сеанс». Защиты: встроенный администратор (учётная запись с SID на -500) не удаляется и не отключается отсюда, последний включённый администратор не удаляется и не отключается. Доменные учётные записи не управляются. Каждое изменение подтверждается и пишется в журнал аудита (`win.users.*`, без паролей).
- **Обновления.** Поиск Windows Update на самом компьютере (может занять минуту; если компьютер работает через WSUS, ответ приходит оттуда): название, KB, размер, важность, «безопасность». Установка выбранных или всех обновлений с живым журналом (загрузка, установка, коды результата, нужна ли перезагрузка). На дашборде показывается число обновлений и «нужна перезагрузка», как у apt; агент ищет обновления раз в час, первый раз через 3 минуты после запуска. Программы других производителей (winget) не охватываются.
- **Программы.** Список установленных программ только для просмотра: название, версия, издатель, дата установки, размер и для кого поставлена (весь компьютер с разрядностью x64/x86 или отдельный пользователь). Агент читает разделы реестра Uninstall (компьютер в 64- и 32-разрядном виде и загруженные профили пользователей), ничего не запускает и не удаляет. Системные компоненты, обновления Windows (KB) и записи без названия не показываются, одна программа, видимая в обоих видах реестра, показывается один раз. Есть поиск по названию и издателю и сортировка по столбцам. Модуль `programs` (`modules: programs: true|false` в `agent.yaml`), оператору нужно право `programs`. С агентом старой версии вкладка просит обновить агента.
- **Сеть.** Адаптеры: состояние, DHCP или статический режим, адреса IPv4, шлюз, DNS, MAC, скорость, MTU. Изменение одного адаптера (DHCP, либо адрес с длиной префикса и шлюзом, и DNS-серверы). **Если не подтвердить изменение, агент сам отменит его через 30 секунд**: он сохраняет старые настройки и создаёт разовую задачу планировщика (`LinagerNetRollback`), поэтому откат работает, даже если связь пропала. Изменение, оставшееся неподтверждённым после перезапуска, отменяется при запуске агента. Только IPv4; без Wi-Fi, VLAN и объединения интерфейсов. Пока одно изменение ждёт подтверждения, другое не принимается. В аудите `win.network.apply` и `win.network.rollback`.

## Диск
Вкладка «Диск» такая же, как у Linux: тома с занятым и свободным местом и прогнозом, когда место кончится (по истории, которую агент ведёт сам, точка раз в полчаса), что занимает место на томе (дерево папок с размерами и круговая диаграмма: система и программы, профили пользователей, временные файлы, прочее, свободно; сканирование может занять минуту и помечается «неполно», если не закончилось) и способы освободить место. Каждый способ подтверждается, заранее показывает размер и пишется в журнал аудита: временные файлы системы и пользователей, загрузки Windows Update (служба обновления на время остановится), корзина, кэш оптимизации доставки, дампы сбоев и отчёты об ошибках, `Windows.old`. Больше ничего не трогается.

## RDP
Вкладка «RDP» у Windows-сервера (и пункт «RDP» в контекстном меню плитки в «Сетке») показывает экран компьютера и позволяет им управлять: на странице или в плавающем окне, как терминал. Ничего ставить не нужно: RDP-клиент встроен в панель (WebAssembly, подгружается при первом открытии рабочего стола, около 2 МБ в сжатом виде).

Как это работает: клиент в браузере говорит по RDP через WebSocket с панелью, панель пропускает соединение через агента до службы удалённого рабочего стола компьютера (`127.0.0.1:3389` или порт, заданный в Windows). Порт 3389 в сеть не открывается. Вход делается учётной записью Windows (логин, пароль, домен если есть); входит сам клиент (CredSSP), поэтому пароль нигде не хранится и в журнал не попадает. В браузере запоминается только логин. Каждое открытие и закрытие пишется в журнал аудита вместе с введённым логином. Логин и пароль можно не набирать, а выбрать из личного зашифрованного файла «Ключи» (список «Ключ» в форме подключения), см. [Ключи](keys.md).

Что можно: мышь, клавиатура, текстовый буфер обмена в обе стороны (браузер спросит разрешение; по обычному HTTP браузер не даёт доступ к буферу, тогда пункты меню выключены; Ctrl+V сначала отправляет ваш буфер на компьютер, а после Ctrl+C или Cmd+C буфер компьютера попадает в ваш; **на Mac Cmd работает как Ctrl** (Cmd+C, Cmd+V, Cmd+A...), одиночное нажатие Cmd это клавиша Windows), разрешение следует за окном («Ещё» > «Менять разрешение под окно»), масштаб «по размеру окна» или 100%, полный экран. На панели окна есть **Ctrl+Alt+Del** и меню «Ещё»: диспетчер задач, клавиша Windows, блокировка, «Выполнить», Alt+Tab, буфер обмена, масштаб, на весь экран, отключиться. Файлы передаются через проводник.

Что нужно: включённый удалённый рабочий стол в Windows (редакции Pro, Enterprise и Server; Home не подходит). Если он выключен, окно предлагает «Включить удалённый рабочий стол» (подтверждаемое действие с записью в аудит: настройка, группа правил брандмауэра «Удалённый рабочий стол» и служба). Учётная запись с паролем, которой разрешён вход по удалённому рабочему столу (администраторы или группа «Пользователи удалённого рабочего стола»). Один человек за раз: клиентская редакция Windows выгоняет того, кто сидит за компьютером; панель открывает не больше одного рабочего стола на компьютер. Оператору модуль «desktop» выдаётся, как остальные (по умолчанию выключен).

Ограничения: нет звука, принтеров и дисков (используйте проводник), вход по NTLM (доменная учётная запись при политике «Ограничить NTLM» будет отклонена), Kerberos нет. Панели нужна политика CSP с разрешением WebAssembly (`wasm-unsafe-eval`): сервер задаёт её сам.

## Помощник и «Управление»
Вкладка «Помощник» (рядом с «RDP», у неё тоже кнопка «открыть в окне»; кнопка «Помощник» есть и на карточке сервера на дашборде) показывает **экран сеанса Windows** и даёт им управлять: консоль, то есть то, что видит человек за компьютером, или экран чужого сеанса RDP. Пароль не нужен: доступ по правам Linager (модуль «Помощник»), как у Aspia или Radmin. Запроса согласия у пользователя нет, каждое открытие и закрытие пишется в журнал аудита (сеанс, длительность, настройки картинки).

В отличие от «RDP» это не новый RDP-сеанс: человек за компьютером не выгоняется, работает и Windows Home (RDP там нет). Сеанс выбирается кнопкой «Сеанс» в панели окна; кнопка с иконкой монитора задаёт режим отображения: в плавающем окне «Картинка по размеру окна», «Растянуть на всё окно» (картинка занимает всё окно и берёт его пропорции, разрешение компьютера не меняется), «Окно по размеру картинки» (по умолчанию: окно получает размер картинки в 100% и следует за ней), «Окно на весь браузер»; во вкладке «Картинка по размеру окна», «Растянуть на всё окно» и «Картинка 100% (с прокруткой)»; «Полный экран» есть везде. у отключённого сеанса нет экрана, он серый. Один человек за раз на сеанс.

Как это работает: агент (служба, SYSTEM) по запросу запускает в нужном сеансе помощника (`linager.exe agent assistant-helper`, тот же файл) с токеном службы, принятым на номер сеанса. Помощник снимает экран через GDI (работает и в сеансах RDP), сравнивает кадр с предыдущим по плиткам 64×64 и отправляет изменившиеся плитки в JPEG; мышь и клавиатура приходят обратно и идут в `SendInput` (клавиши сканкодами, раскладку выбирает сам Windows). Помощник звонит агенту на порт `127.0.0.1` с одноразовым токеном из переменной среды; агент пересылает байты и разбирает только то, что идёт вверх: Ctrl+Alt+Del он берёт себе (послать его может только служба). Курсор компьютера по умолчанию в кадр не попадает: виден ваш собственный указатель, он двигается без задержки; флажок в «Управлении» включает рисование курсора компьютера в кадре.

Вкладка **«Управление»** (группа «Сеть и защита», только у Windows-серверов) задаёт картинку: готовые наборы «Экономный», «Обычный», «Качественный»; цвета (24 бита, 16 бит, 256 цветов, оттенки серого); верхний предел частоты кадров (1–30); **лимит трафика** в Мбит/с на сеанс (или без лимита). Настоящего видеокодека нет, поэтому «битрейт» это лимит: кодер сам понижает качество JPEG и пропускает кадры, чтобы уложиться (флажок «Само снижать качество»). Изменения действуют сразу и на открытые сеансы. Здесь же включается и выключается **RDP**; пока он выключен (или у Windows Home его нет), вкладка и пункты меню «RDP» на странице сервера и на дашборде скрыты, и появляются снова сразу после включения, без перезагрузки страницы (агент сообщает состояние в каждом замере): выключение (подтверждаемое действие с записью в аудит) запрещает новые подключения по RDP и закрывает правило брандмауэра, а уже открытые сеансы не прерывает; агент и Помощник от RDP не зависят. На Windows Home RDP нет, кнопка недоступна. В таблице «Сеансы Windows сейчас» видно, кто вошёл и откуда, и можно открыть сеанс в Помощнике.

Права: модуль «Помощник» выдаётся оператору отдельно от «RDP» (по умолчанию выключен); включение и выключение RDP требует права «Рабочий стол». Модуль можно выключить на самом компьютере в `C:\ProgramData\Linager\agent.yaml` (`assistant: false`).

**Экран блокировки, вход и UAC.** Они идут на отдельном рабочем столе Windows (Winlogon). Помощник каждую секунду проверяет, на какой рабочий стол Windows сейчас отправляет ввод, и переходит на него, поэтому блокировка, экран входа (когда на консоли никого нет) и запрос UAC видны и управляются; в строке под экраном и в заголовке появляется метка «UAC». На этих экранах на панели есть **кнопка с ключом**: она печатает логин и пароль из личного файла «Ключи» (логин, пароль или вход целиком), см. [Ключи](keys.md). **Ctrl+Alt+Del** работает на консоли (в чужой RDP-сеанс служба послать его не может, кнопка там выключена); Windows должен это разрешить: в «Управлении» есть переключатель политики «Software SAS generation» (подтверждаемое действие, запись в аудит). **Буфер обмена** (текст до 1 МБ) работает обычными сочетаниями: Ctrl+V отправляет текст вашего буфера и вставляет его на компьютере (браузер отдаёт текст сам, разрешение не нужно), Ctrl+C и Ctrl+X забирают скопированное на компьютере в ваш буфер (браузер может спросить разрешение; по HTTP доступа к буферу нет). На Mac Cmd работает как Ctrl (Cmd+C, Cmd+V, Cmd+A...), одиночное нажатие Cmd это клавиша Windows. Те же действия есть в меню «Отправить мой буфер обмена» и «Забрать буфер обмена компьютера»; передача только по вашему действию. **Несколько мониторов:** в меню «Ещё» выбирается монитор или «Все мониторы» одной картинкой. **Диспетчер:** кнопка с иконкой на панели (рядом с «Файлы», есть на всех подключениях и у тех, у кого есть права «Процессы» или «Службы») открывает плавающее окно в духе диспетчера задач, одно на сервер, закрывается крестиком. Вкладка «Процессы»: список с живым обновлением (раз в 3 с), сортировка по любому столбцу (процесс, PID, пользователь, ЦП, ОЗУ; повторный клик меняет порядок), итоги ЦП и ОЗУ в заголовках, ячейки теплеют с нагрузкой; внизу «Завершить» и «Принудительно завершить» (оба с подтверждением и записью в аудит; обычное завершает только этот процесс, принудительное ещё и все процессы, которые он запустил; Windows не даёт службе мягко закрыть окно в сеансе человека, поэтому данные, не сохранённые в процессе, пропадают в обоих случаях). Системные процессы и сам агент завершить нельзя. Вкладка «Службы»: фильтры «Все / Работают / Остановлены / Упавшие», сортировка по столбцу, внизу «Перезапустить» и «Остановить» для работающей службы и «Запустить» для остановленной или упавшей; защищённые службы (агент Linager, удалённый рабочий стол и другие) спрашивают подтверждение. **Строка под экраном** (разрешение, цвета, кадры, трафик) по умолчанию скрыта и включается пунктом «Информация» в меню «Ещё» (галочка значит «показана»); выбор один для всех окон и вкладок Помощника и запоминается в браузере. Рамки фокуса вокруг экрана нет. Пункт «Качество и частота кадров…» открывает те же настройки картинки, что и вкладка «Управление», **в небольшом плавающем окне** (по одному на сервер; работает и в Консоли), так что качество можно менять рядом с экраном и сразу видеть кадры и трафик в строке под ним.

Ограничения: нет звука и передачи файлов (есть проводник), нет записи сеанса, нельзя подключиться к отключённому сеансу. Помощник работает от SYSTEM, как служба: антивирус и EDR могут ругаться на процесс, который снимает экран и вводит клавиши; для `linager.exe` нужно исключение.

## Файлы, журнал и удаление
- `C:\ProgramData\Linager\agent\` ключи и состояние; `C:\ProgramData\Linager\agent.yaml` (модули, необязателен, формат как в Linux: `modules:` со значениями `true` / `false`); `C:\ProgramData\Linager\agent.log` журнал (файл больше 5 МБ переименовывается в `agent.log.1`). Папка `C:\ProgramData\Linager` открыта только SYSTEM и администраторам: это аналог прав 600 у Linux-агента.
- `linager.exe agent status` показывает версию, сервер и состояние службы.
- После правки `agent.yaml` перезапустите службу: `Restart-Service LinagerAgent`.
- Удаление: `msiexec /x linager-agent_windows_amd64.msi /qn`. Ключи, журнал и адрес сервера остаются; чтобы убрать и их, удалите `C:\ProgramData\Linager` и раздел `HKLM\SOFTWARE\Linager`. «Удалить сервер» в панели заставляет агента убрать свою привязку и службу.

## Обновление
Из панели, как у Linux-агента: страница «Обновления» (один агент, выбранные или все). Сервер отдаёт агенту подписанный `linager-agent_windows_amd64.exe` своего релиза (тот же файл, что ставит MSI). Агент проверяет подпись манифеста и контрольную сумму, сохраняет работающий exe как `C:\ProgramData\Linager\agent\linager.prev.exe`, отодвигает запущенный файл (Windows разрешает переименовать работающую программу, но не перезаписать), ставит новый на его место и перезапускает службу. Стадии те же, что в Linux (загрузка, проверка, резерв, замена, перезапуск, офлайн, повторное подключение, подтверждение).

**Откат.** Перед перезапуском агент создаёт разовую задачу планировщика Windows `LinagerAgentRollback` (от SYSTEM, примерно через 70 секунд). Новая версия подтверждает себя первым подключением к серверу и удаляет задачу. Если этого не произошло (не запустилась или не достучалась до сервера), задача запускает СТАРЫЙ exe: он останавливает службу, возвращает старый файл и снова запускает службу. Вручную: `linager.exe agent update`, `linager.exe agent status`.

**Агент из пред-релизной сборки старше `0.3.0-beta.4` из панели обновить нельзя** (в нём нет нужного кода): в таблице стоит «новый MSI X». Один раз поставьте MSI версии `0.3.0` или новее, после этого панель обновляет агент. Та же пометка появляется, если в релизе нет Windows-файла. В списке программ Windows (продукт MSI) после обновления из панели остаётся версия MSI: на работу агента это не влияет, следующий MSI ставится поверх как обычно. Сервер того же релиза нужно обновить раньше, как и для Linux-агентов.

## Ограничения
- Только x64. Агент обновляется из панели; откат неудачного обновления проверен на Windows-раннере и на одной тестовой машине. Exe и MSI не подписаны сертификатом подписи кода, поэтому SmartScreen или антивирус могут предупреждать.
- Проверено: код собирается и тестируется на Windows-раннере GitHub Actions (метрики, службы, процессы, файлы, терминал, установка и удаление MSI). На реальном парке не проверялось.
- Windows 11 в реестре называется «Windows 10»; агент различает их по номеру сборки (22000 и выше).
