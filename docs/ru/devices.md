# Устройства

«Настройки» в приложении → **Устройства**: список приложений (настольное приложение, приложение для iPhone, позже Android), которые входят на сервер, и подтверждение новых устройств. Раздел только для администратора.

## Что такое устройство

При первом запуске приложение делает случайный секретный токен (256 бит) и хранит его в защищённом хранилище: на iPhone в Keychain, на компьютере в хранилище ключей системы. Токен уходит на сервер в заголовке `X-Linager-Device`, сервер хранит только его хэш. Заголовок `X-Linager-Client` рассказывает, что это за приложение (`platform=ios&app=0.1.0&os=27.1&model=iPhone18%2C1`). Устройство принадлежит одному пользователю: один телефон под двумя учётными записями это два устройства. Переустановка приложения даёт новое устройство.

В таблице видно: устройство (модель и ваше название), пользователя, версию приложения, версию ОС, последний IP, время последней активности и состояние. Последний IP сервер берёт из самих запросов, а не из слов приложения. Список ведётся всегда, и при выключенном подтверждении.

## Подтверждение

После установки сервера подтверждение **выключено**. Администратор включает его в приложении (переключатель «Подтверждать устройства»). После этого **любое** подключение, даже с разрешённого IP, требует подтверждения, как у агентов при ручной установке:

1. Новое устройство входит с логином, паролем и кодом 2FA. Сессия открывается, но устройство в состоянии «ждёт подтверждения»: сервер отвечает на всё, кроме «кто я» и выхода, кодом 403 `approval_pending`. На устройстве показывается заглушка «Ожидает подтверждения».
2. Администратор видит заявку в «Устройствах» (устройство, пользователь, версия, IP, время) и нажимает «Разрешить» или «Отклонить». Сам себя администратор подтвердить может, но только из настольного приложения уже подтверждённого устройства.
3. Подтверждённое устройство при следующем входе проходит без вопросов. Отклонённое входить не может (403 `device_denied`). «Удалить» стирает устройство и сразу выводит его из системы.
4. Каждое решение пишется в журнал аудита: `device.request`, `device.approve`, `device.deny`, `device.remove`, `device.label`, `device.gate.on`, `device.gate.off`.

Пока подтверждение включено, одной cookie сессии мало: каждый запрос должен прийти с токеном устройства. Украденная cookie без токена не работает (401). Клиент вообще без токена (старая версия приложения) не может войти (403 `device_required`): обновите приложение.

### Включение

Включить можно только из приложения, у которого уже есть устройство: оно подтверждается само, иначе администратор запер бы себя. Сервер спрашивает подтверждение и предлагает выбор:

- **Оставить открытые сессии**: уже вошедшие устройства остаются, их считают подтверждёнными (стоит просмотреть список и удалить лишнее);
- **Выйти везде, кроме этого устройства**: все остальные входят заново и проходят подтверждение. Выбирайте, если сомневаетесь в открытых сессиях.

### Если вход потерян

Если подтверждение включено, а подтверждённого устройства не осталось, на сервере выполните:

```bash
linager server devices list          # устройства и состояние подтверждения
linager server devices approve <id>  # подтвердить устройство
linager server devices off           # выключить подтверждение (без перезапуска)
```

Команды пишут в журнал аудита (исполнитель `cli`). Кто может запустить их, уже владеет сервером.

## Чего это не делает

Подтверждение не заменяет пароль, 2FA и ограничение по адресу, а добавляется к ним третьим рубежом: чужой телефон с утёкшим паролем и кодом без вашего ведома не войдёт. Сессии, открытые в момент включения (вариант «оставить открытые сессии»), считаются подтверждёнными.
