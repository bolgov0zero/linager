# Установка Linager

Поддерживаются Debian 12/13 и Ubuntu 22.04/24.04/26.04 (amd64, systemd). Агент также работает на arm64, например на Raspberry Pi 4 с Raspberry Pi OS 64-bit (Debian 12/13). 32-разрядные системы не поддерживаются, сервер на arm64 тоже.

## Быстрая установка

```bash
curl -fsSL https://raw.githubusercontent.com/bolgov0zero/linager/main/install.sh | sh
```

Команду нужно выполнять от root, иначе установщик завершится с ошибкой.

**После установки откроется меню Linager** (то же, что покажет команда `linager` без аргументов, см. [menu.md](menu.md)): когда мастер закончит и покажет итоги (адреса, пароль администратора), скрипт попросит нажать Enter и откроет меню. Так же ведёт себя установка по ссылке (ниже). Меню не открывается, если установка не удалась, если нет терминала (автоматизация) или если задан `--no-tui`.

## Безопасный вариант: скачать, проверить, запустить

```bash
curl -fsSLO https://raw.githubusercontent.com/bolgov0zero/linager/main/install.sh
less install.sh                      # прочитайте скрипт
sudo sh install.sh
```

Скрипт очищает экран, проверяет систему, скачивает релиз, сверяет контрольную сумму и подпись minisign (ключ вшит в скрипт) и запускает мастер `linager install`.

## Мастер

Первый вопрос: что ставить, **Сервер** или **Клиент**.

### Сервер
Вопросы (порты обязательны, значений по умолчанию нет):

| Вопрос | Пояснение |
|---|---|
| Порт для клиентов | клиенты подключаются сюда напрямую по TLS |
| Порт приложения | сюда подключается приложение Linager по TLS ([подключение](connection.md)) |
| Логин и пароль | пароль от 12 символов; пусто — сгенерировать и показать один раз |

Этапы: проверка системы, PostgreSQL (из репозитория ОС, только localhost, `scram-sha-256`), база и роль со случайным паролем, конфигурация `/etc/linager/server.yaml` (права 600, владелец `linager`) и ключи, администратор, служба `linager-server`, проверка запуска (отвечает порт приложения). Ход установки пишется в `/var/log/linager-install.log`.

Веб-панели нет: управляют сервером из приложения Linager. Порт приложения принимает прямое TLS-соединение (перед ним не нужен прокси); откройте его в файрволе. Ограничить, кто может подключаться, можно в приложении, в «Настройки → Доступ к серверу» ([access.md](access.md)). Необязательный флаг `--domain` добавляет DNS-имя сервера в сертификат.

В итоге показываются адрес и порт приложения, отпечаток сертификата, логин администратора (и пароль, если он сгенерирован) и готовая команда установки клиента. Адрес и отпечаток можно показать позже командой `linager server app-port`; она же включает порт приложения у сервера, где его нет.

### Клиент
Вопросы: адрес сервера `host:порт клиентов` и подтверждение отпечатка (или флаг `--fingerprint`). Затем мастер показывает **ключ** `XXXX-XXXX` и **код сверки**. Введите ключ в приложении («Добавить сервер» → «Подтверждения», блок «Ждут подтверждения») и убедитесь, что коды совпадают. После подтверждения запускается служба `linager-agent`. Адрес, порт и отпечаток для этого вопроса можно взять в приложении: «Добавить сервер» → «Подтверждения», блок «Данные для подключения клиента».

Два способа обойтись без мастера и без ключа: установка по ссылке и установка по SSH (ниже).

### Установка по ссылке
В «Добавить сервер» → «Установка по ссылке» создайте ссылку: срок действия (15 минут, 1 час, 24 часа, 7 дней), число серверов (1, 5, 10, 25 или без ограничения), необязательно группу и разрешённые сети. Приложение покажет **две команды**: внешнюю (по адресу, видимому из интернета) и локальную (по адресу в вашей сети). Выполните нужную на новом сервере от root (без `sudo`: в некоторых системах его нет; нужен `wget`, он входит в базовую систему Debian и Ubuntu):

```bash
wget -nv -O- --no-check-certificate --pinnedpubkey 'sha256//…' 'https://panel.example.com:9443/v1/join/lk_…' | sh
```

Скрипт определяет ОС и архитектуру, берёт бинарник **с вашего сервера** (из кеша подписанных релизов, без GitHub), сверяет его с подписанным манифестом и запускает `linager install agent --join-token …`. Сервер появляется во вкладке «Подтверждения» с пометкой «по ссылке»: ключ вводить не нужно, достаточно нажать «Подтвердить». Если у ссылки включено «Одобрять серверы автоматически», сервер добавляется сразу. Имя сервера агент сообщает сам.

- Сервер в команде проверяется закреплением ключа (`--pinnedpubkey`), поэтому `--no-check-certificate` не открывает путь для подмены: отвечать должен именно ваш сервер.
- Токен виден **один раз**, при создании. Сервер хранит только его хеш. Ссылку можно отозвать в блоке «Действующие ссылки».
- Скрипт можно прочитать до запуска: кнопка «Показать скрипт» или та же команда `wget` без `| sh`.
- Ссылка с вышедшим сроком или с исчерпанным числом использований перестаёт работать сама. Ограничение по сетям проверяет адрес, с которого хост обращается к серверу.
- Адреса для команд берутся из `agents.hosts` в `server.yaml` (имена и адреса сертификата порта клиентов) и из адреса, по которому приложение подключено к серверу.
- Вручную: `sudo linager install agent --server host:порт --fingerprint SHA256:… --join-token lk_…` и `linager agent enroll … --join-token …`.

### Установка по SSH
В «Добавить сервер» → «Установка по SSH» введите адрес, порт, логин и пароль (или закрытый ключ) нового сервера. Сервер подключится сам и поставит агента; подтверждать запрос не нужно: вход по SSH уже показал, что сервер ваш.

1. **Проверка.** Приложение показывает отпечаток ключа хоста (сверьте его с консолью или панелью хостинга: иначе пароль можно отдать подставному хосту), затем проверяет вход, систему (Debian 12/13, Ubuntu 22.04/24.04/26.04, amd64 или arm64), systemd и место на диске, права (root, `sudo` без пароля или `sudo` с паролем: он запрашивается и нужен только на время установки), **доступность порта клиентов сервера с самого хоста** (с выбором другого адреса сервера) и наличие уже установленного агента (его можно переустановить).
2. **Установка.** Одноразовый токен (10 минут, один сервер, автоодобрение), загрузка агента с сервера, проверка по подписанному манифесту, `linager install agent`, привязка, первое подключение агента. Вывод команд виден в блоке «Вывод».
3. **Откат.** Если агент не подключился за 60 секунд или установщик упал, сервер удаляет агента с хоста (`agent uninstall --purge`) и запись сервера: хост остаётся как был.

Безопасность:
- Пароль, ключ и пароль `sudo` хранятся только в памяти сервера, пока идут проверка и установка (не дольше 15 минут без обращений), и нигде не записываются, в том числе в журнал и в аудит. В аудит попадают адрес, логин и результат. Пароль принимается только по TLS (порт приложения шифрует соединение).
- Сервер отказывается подключаться к адресам loopback, link-local (`169.254.0.0/16`, метаданные облака) и multicast. Круг адресов можно сузить в `server.yaml`: `ssh_install.allowed_networks: ["10.0.0.0/8", "192.168.0.0/16"]`.
- Не больше трёх открытых установок на администратора и десять проверок за десять минут.
- Хосты, где вход по SSH требует второго фактора (`keyboard-interactive` с кодом), не поддерживаются: для них используйте установку по ссылке.

## Без вопросов (автоматизация)

```bash
sudo linager install server --no-tui --agent-port 9443 --app-port 9444 --admin-user admin
sudo linager install server --no-tui --agent-port 9443 --app-port 9444 --domain linager.example.com
sudo linager install agent  --no-tui --server 10.0.0.5:9443 --fingerprint SHA256:...
```

Без терминала или с `--no-tui` вопросы не задаются: все обязательные параметры берутся из флагов. `--lang ru|en` выбирает язык, `--force` разрешает повторную установку, `--admin-password-file` задаёт пароль из файла.

## Удаление клиента
В приложении: карточка сервера, «Удалить». Можно сразу удалить агента с хоста. Вручную на хосте: `sudo linager agent uninstall --purge`.
