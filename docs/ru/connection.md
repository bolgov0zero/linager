# Подключение: порты агентов и приложения

«Настройки» → **Подключение** показывает и меняет два порта сервера. Изменение применяется сразу, сервер перезапускать не нужно. Раздел виден администратору.

| Порт | Что на нём | Кто подключается |
|---|---|---|
| Порт агентов | TLS 1.3, взаимная проверка сертификатов | агенты на управляемых серверах |
| Порт приложения | TLS 1.3 с сертификатом порта агентов, тот же API, что у админки | приложение Linager |

Порт админки (за Caddy или своим прокси) здесь не меняется: он задаётся при установке в `server.yaml`.

Сертификат у обоих портов один, поэтому в разделе показан один отпечаток (SHA-256). Приложение запоминает его при первом подключении, как SSH запоминает ключ хоста.

## Порт приложения

Это отдельный порт: прямое TLS-соединение без обратного прокси. Мастер установки спрашивает его всегда (`--app-port` в режиме без вопросов). На сервере, который был установлен раньше, порт не задан: введите его в разделе «Подключение». Пустое поле выключает порт.

- Заголовки обратного прокси (`X-Forwarded-For`, `X-Real-IP`, `Forwarded` и подобные) на этом порту отбрасываются: клиент не может назвать свой адрес. Ограничение доступа к админке и лимиты входа видят настоящий адрес соединения.
- Порт нужно открыть в файрволе (мастер напоминает об этом, если активен nftables).
- Значение из «Подключения» хранится в базе и сильнее `server.yaml` (служба не может писать в `/etc/linager`). В `server.yaml` порт задаёт мастер: `app.listen: "0.0.0.0:ПОРТ"`.

## Смена порта агентов

Агент хранит адрес сервера у себя, поэтому порт нельзя просто переключить: агенты потеряли бы связь. Переезд идёт так:

1. Сервер открывает новый порт, **старый остаётся открытым**.
2. Каждому подключённому агенту он отправляет подписанное сообщение с новым портом. Хост агент берёт прежний, меняется только порт.
3. Агент сохраняет новый адрес и подключается к нему первым. Первое подключение, которое сработало, делает новый порт основным.
4. Если новый порт не работает (файрвол, опечатка), после трёх неудачных попыток агент возвращается на старый порт, а тот же порт игнорирует час.
5. Агент, который был не в сети, получит сообщение при подключении к старому порту.
6. Когда все зарегистрированные агенты перешли, старый порт закрывается сам. Ход виден в разделе: «перешло N из M» и список тех, кто ждёт.

Ограничения:
- Агент понимает переезд с версии **0.10.0-beta.1**. Пока в сети есть агент старее, порт агентов сменить нельзя: раздел перечисляет такие агенты. Обновите их, потом меняйте порт. Старый агент, который не в сети, не мешает: он будет ждать на старом порту, пока вы его не обновите.
- Пока идёт переезд, порт агентов сменить ещё раз нельзя.
- Кнопка **«Закрыть старый порт»** закрывает его сразу; агенты, которые не перешли, потеряют связь (с подтверждением).
- Установочные ссылки и команды, созданные раньше, содержат старый порт и перестают работать после его закрытия.
- Новый порт нужно открыть в файрволе сервера и сети заранее.

Все изменения пишутся в журнал аудита (`connection.update`, `connection.close_old`).

## API

`GET /api/connection`, `PUT /api/connection` (`{"agent_port": N, "app_port": N}`, 0 выключает порт приложения), `POST /api/connection/close-old`. Только для администратора.
